# SeedWork.Persistence.EFCore — план реализации

## Назначение и границы

Необязательный NuGet-адаптер для сервисов на EF Core и .NET 10. Он связывает EF Core с типами `SeedWork.Domain`, сохраняя выбор провайдера БД, схему, миграции и транзакционную политику за сервисом. Зависит от `SeedWork.Domain` и EF Core; доменный пакет от него не зависит.

## Публичный API первой версии

- `AddSeedWorkDbContext<TContext>(IServiceCollection, Action<IServiceProvider, DbContextOptionsBuilder>)` регистрирует `TContext : DbContext` обычным `AddDbContext`. Переданный сервисом callback полностью задаёт провайдер и его опции; пакет не задаёт строку подключения, пул или retries.
- `IgnoreDomainEvents<TEntity>(EntityTypeBuilder<TEntity>) where TEntity : class, IAggregateRoot` исключает коллекцию доменных событий из модели EF Core. Сервис вызывает метод в конфигурации своих агрегатов; прочее отображение остаётся в сервисе.
- `GetTrackedAggregatesWithEvents(ChangeTracker)` возвращает отслеживаемые `IAggregateRoot` с непустой коллекцией доменных событий. Метод использует `DomainEvents` из контракта `IAggregateRoot` и не вызывает `ClearDomainEvents()`.
- Отображение конкретных ID и объектов-значений задаётся в конфигурации модели сервиса. Общие конвертеры вводить только для реально общего доменного типа, появившегося в `SeedWork.Domain`.

Адаптер не вызывает `SaveChanges` автоматически, не отправляет события и не создаёт транзакцию вокруг произвольного сценария. Сервис решает порядок сохранения и отправки; интеграционные события требуют отдельного решения об outbox в плане шины.

## Этапы реализации

1. Создать проект адаптера и проект интеграционных тестов после выпуска контракта `IAggregateRoot` из плана домена.
2. Реализовать регистрацию контекста через переданный callback без зависимости от Npgsql, SQL Server или другого провайдера.
3. Реализовать исключение событий из модели и поиск агрегатов с событиями через `ChangeTracker`; задокументировать, что поиск не очищает события.
4. Добавить пример конфигурации модели и регистрации провайдера в сервисе; собрать и упаковать адаптер отдельно.

## Проверки и критерий готовности

- Интеграционные тесты на SQLite in-memory проверяют создание контекста, сохранение и чтение агрегата без отображения коллекции событий в БД.
- Проверить, что выборка событий учитывает только отслеживаемые агрегаты и не удаляет события; исключение при сохранении не вызывает их очистку.
- Пакет собирается без провайдера PostgreSQL; сервис может подключить свой провайдер независимо. `dotnet test` и `dotnet pack` проходят.

## Зависимости

Требуется готовый контракт `SeedWork.Domain`. Реализацию этого адаптера можно выполнять независимо от планов приложения, шины, файлового хранилища и телеметрии.
