# SeedWork.Domain — план реализации

## Назначение и границы

Небольшой NuGet-пакет с общими механизмами доменной модели для сервисов на .NET 10. Бизнес-сущности, правила, идентификаторы и события каждого ограниченного контекста остаются в самом сервисе. Пакет не зависит от EF Core, MediatR, Aspire, DI и других пакетов SeedWork.

## Публичный API первой версии

- `Entity<TId>` хранит неизменяемый после создания `Id` и определяет равенство сущностей одного конкретного типа по непустому идентификатору. Для сущностей без назначенного идентификатора действует равенство по ссылке; хеш-код согласован с этим правилом.
- `IAggregateRoot` обозначает корень агрегата и открывает `IReadOnlyCollection<IDomainEvent> DomainEvents` и `ClearDomainEvents()`. `AggregateRoot<TId> : Entity<TId>, IAggregateRoot` хранит события в порядке добавления и предоставляет защищённый `AddDomainEvent(IDomainEvent)`. Добавление `null` запрещено.
- `IDomainEvent` — пустой интерфейс. Конкретное событие и его данные определяет сервис; время создания и идентификатор события не навязываются базовым пакетом.
- Объекты-значения рекомендуются как неизменяемые C# `record`/`record struct`; отдельный базовый класс `ValueObject` в первой версии не нужен.

Пакет не публикует события и не определяет момент их обработки. Очистка коллекции событий происходит только после решения вызывающего кода о том, что события успешно переданы выбранному диспетчеру. Не включать универсальный репозиторий, `Result<T>`, типизированные ID и исключения без подтверждённого повторяющегося сценария.

## Этапы реализации

1. Создать проект `SeedWork.Domain` с `net10.0`, nullable reference types и настройками NuGet-пакета; добавить его в решение.
2. Реализовать публичные типы и XML-документацию с явным описанием равенства и жизненного цикла событий.
3. Создать отдельный проект тестов. Проверить совместимость API без сторонних зависимостей и подготовить короткий пример агрегата в документации пакета.
4. Собрать и упаковать пакет; проверить, что его список зависимостей не содержит инфраструктурных библиотек.

## Проверки и критерий готовности

- Тесты покрывают равенство сущностей одного и разных типов, назначенный и пустой ID, согласованность `Equals`/`GetHashCode`, порядок событий, повторную очистку и запрет `null`.
- Пример сервиса может определить собственные агрегат и событие без ссылок на другие пакеты SeedWork.
- `dotnet test` и `dotnet pack` проходят; пакет подключается как самостоятельная зависимость.

## Связи с другими планами

`SeedWork.Application` не обязан ссылаться на этот пакет. Адаптер EF Core может использовать `IAggregateRoot` для поиска отслеживаемых агрегатов. Сам домен ничего не знает об этих интеграциях.
