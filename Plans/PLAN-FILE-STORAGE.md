# SeedWork.FileStorage — план реализации контракта

## Назначение и границы

Небольшой NuGet-пакет с портом для работы с файлами в сервисах на .NET 10. Первая версия содержит только контракт: локальная файловая система, S3 и другие провайдеры могут быть добавлены позже отдельными пакетами. Ключ файла — непустой непрозрачный идентификатор в пространстве имён конкретного сервиса; контракт не приравнивает его к пути ОС или URL.

## Публичный API первой версии

- `IFileStorage.PutAsync(string key, Stream content, CancellationToken cancellationToken = default)` сохраняет содержимое; повторная запись по тому же ключу заменяет объект.
- `IFileStorage.OpenReadAsync(string key, CancellationToken cancellationToken = default)` возвращает поток для чтения; отсутствие ключа выражается `FileNotFoundException`.
- `IFileStorage.DeleteAsync(string key, CancellationToken cancellationToken = default)` возвращает `bool`: `true`, если объект существовал и был удалён, `false` — если его не было.

Вызывающий код владеет входным и возвращённым потоками и освобождает их. Реализация не закрывает поток, переданный в `PutAsync`; возвращённый поток освобождает вызывающий код. Реализация обязана соблюдать отмену там, где провайдер её поддерживает. Список файлов, публичные ссылки, ACL, версии объектов и метаданные не входят в первую версию.

## Этапы реализации

1. Создать `SeedWork.FileStorage` с `net10.0`, nullable reference types и упаковкой в NuGet; добавить интерфейс и XML-документацию семантики операций.
2. Добавить пример сервиса, который использует порт через DI и не знает о конкретном провайдере.
3. Сделать тестовую реализацию в тестовом проекте для проверки контракта потребителя. Не публиковать её как производственный адаптер.
4. Собрать и упаковать контракт без зависимостей от SDK облачных хранилищ.

## Проверки и критерий готовности

- Тесты потребителя проверяют потоковую передачу содержимого, замену существующего ключа, отсутствие файла, идемпотентное удаление и передачу отмены.
- В документации явно указаны владение потоками и отсутствие гарантий атомарности между файловым хранилищем и БД.
- `dotnet test` и `dotnet pack` проходят; контракт доступен без подключения конкретного провайдера.

## Следующий этап

Перед первым производственным адаптером отдельно выбрать провайдера и зафиксировать ограничения его API, настройку доступа, размеры файлов и способ тестирования. Это решение не требуется для выпуска контракта.
