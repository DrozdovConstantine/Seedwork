# SeedWork.Application — план реализации

## Назначение и границы

NuGet-пакет для единых минимальных контрактов прикладных сценариев в .NET 10. Сценарий координирует доменные объекты и порты своего сервиса; бизнес-правила находятся в домене. Пакет не выбирает MediatR, CQRS, библиотеку валидации, способ регистрации DI или формат HTTP-ответа.

## Публичный API первой версии

- `IUseCase<TRequest, TResponse>` с `Task<TResponse> ExecuteAsync(TRequest request, CancellationToken cancellationToken = default)`.
- `IUseCase<TRequest>` с `Task ExecuteAsync(TRequest request, CancellationToken cancellationToken = default)` для операций без результата.
- Запросы и ответы определяет сервис. Интерфейсы не требуют наследования от общих `Command`, `Query` или `Result`.

Только эти контракты входят в первую версию. Использование DI, выбор транзакции, валидация, авторизация, преобразование ошибок и доставка доменных событий остаются в композиции конкретного сервиса. Пакет не вводит автоматический pipeline или сканирование сборок.

## Этапы реализации

1. Создать `SeedWork.Application` для `net10.0`, включить nullable reference types и упаковку в NuGet.
2. Реализовать два интерфейса и документировать правило передачи `CancellationToken` всем внешним асинхронным операциям сценария.
3. Добавить пример простого сценария и его явной регистрации в DI сервиса; показать применение без диспетчера и без обязательной ссылки на `SeedWork.Domain`.
4. Собрать и упаковать пакет отдельно от инфраструктурных адаптеров.

## Проверки и критерий готовности

- Компиляционный пример подтверждает реализацию обоих интерфейсов обычными классами сервиса.
- Тест примера проверяет передачу отмены во внешний порт и сохранение исходной ошибки без скрытого преобразования.
- В графе зависимостей пакета нет MediatR, FluentValidation, EF Core и Aspire; `dotnet test` и `dotnet pack` проходят.

## Отложенные расширения

Если несколько сервисов подтвердят одну и ту же потребность, диспетчер сценариев, CQRS-маркеры или pipeline оформляются отдельным пакетом и решением о версии API. Их не добавлять в базовый пакет заранее.
